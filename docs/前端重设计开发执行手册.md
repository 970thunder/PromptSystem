# PromptOS 前端重设计开发执行手册

> 状态：当前执行基线 v1.0
>
> 适用范围：`src/frontend/` 的产品体验、页面结构、导航、主题和社区交互重设计。
>
> 本文件是下一轮前端开发的唯一执行清单。

## 1. 先做产品取舍

### 1.1 产品定位

PromptOS 是一个“发现、拆解、收藏、发布和复用 AI 提示词的社区”。

首要用户任务只有三件事：

1. 找到一个能解决当前问题的 Prompt。
2. 在详情页看懂结构、复制或收藏，并判断是否可信。
3. 把验证过的方法发布出来，与作者和其他使用者交流。

### 1.2 本轮做与不做

本轮必须完成：Prompt 发现信息流、搜索与筛选、Prompt 详情、发布、作者主页、登录注册、点赞/收藏/关注/评论/举报、全局导航、明暗主题和响应式可访问性。

本轮不新增没有后端契约的独立业务：Skill 运行器、Playground、学院课程、比赛报名、交易市场、企业空间、Agent 编排。它们可以出现在导航的“规划中”说明中，但不能伪装成可用入口，也不能用假页面占位。

### 1.3 体验判断标准

- 首页 5 秒内通过品牌、标语和入口让用户知道这是 Prompt 社区，不依赖解释性长文。
- 首页是简洁的产品入口，不是营销长页；首屏底部必须露出一部分真实信息流。
- 进入发现/搜索/详情/工作台后，才显示密集信息、筛选和操作。
- 顶部导航在所有正常页面保持一致；超级菜单展开时真实向下推开内容。
- 任何统计、作者、评论、互动状态都必须来自接口或明确标注为演示数据。
- 任何链接都必须到达真实页面或带有解释的禁用状态，禁止“点击无反应”。

## 2. 项目事实与边界

| 区域 | 当前事实 | 重构约束 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vite、TailwindCSS、Pinia、Vue Router 4、Naive UI | 延续现有栈，不引入第二套 UI 框架 |
| 外壳 | 已有 `AppShell`、`SiteHeader`、`MegaMenu`、`ThemeToggle` 雏形 | 外壳集中维护，视图不得复制 Header |
| 路由 | `/`、`/search`、`/prompt/:id`、`/publish`、`/profile/:userId?`、认证路由 | 先修复现有路由体验，不新增无 API 页面 |
| 数据 | Prompt、分类、用户、评论、互动和 `/home/summary` 已有 API/Store | 页面状态以 Store/API 为准，禁止在 View 内重复造数据层 |
| 主题 | 已有 `tokens.css`、`useSiteTheme`，目标属性为 `html[data-mode]` | 统一 `light/dark/system`，首屏防闪烁 |
| 后端 | Go + `net/http` + MySQL/内存降级；互动接口幂等 | 前端先适配现有契约；需要新增接口时先改 `docs/API契约.md` |

开始任何任务前，AI 必须读取本手册、`README.md`、目标源码和当前 `git diff`，保留不属于本任务的工作树改动。

## 3. 信息架构与路由契约

### 3.1 全局导航

桌面端顶部结构：品牌 Logo、一级入口“发现/社区/我的”、搜索入口、发布入口、主题按钮、用户入口。一级入口通过一个全宽超级菜单展开；菜单内容按“发现内容、参与社区、个人工作台、即将开放”分组。

移动端保留相同信息架构，使用顶部按钮展开文档流折叠面板；不复制一套不同命名的移动导航。

真实目标约定：

| 入口 | URL | 说明 |
| --- | --- | --- |
| 发现全部 | `/search` | 默认最新排序 |
| 最新 | `/search?sort=latest` | `latest` |
| 热门 | `/search?sort=popular` | `popular` |
| 图像/文案/代码 | `/search?keyword=图像` 等 | 关键词筛选 |
| 工作流/智能体 | `/search?tag=流程`、`/search?tag=智能体` | 标签筛选，不使用无效 `tab` |
| 发布 | `/publish` | 未登录转 `/login?redirect=/publish` |
| 我的工作台 | `/profile` | 未登录转登录，并保留安全的内部 redirect |
| 作者 | `/profile/:userId` | 公开查看；只有编辑本人时需要登录 |

`SearchView` 必须从 URL 恢复筛选、排序、分页，筛选变化更新 URL；刷新和浏览器返回后结果与控件一致。

### 3.2 页面模板

**首页 `/`**

- 首屏只保留品牌、短标语、一个主 CTA（开始探索）和一个弱化的发布入口；推荐标语：`好提示词，马上复用。`
- 标语下最多一行辅助文案：`发现、拆解并分享可复用的 AI 提示词。` 不再写产品说明、教程、愿景或内部术语。
- 不放“三步使用方法”、长段 FAQ、虚假统计或解释型 feature grid；产品能力通过真实导航、筛选和内容本身表达。
- 首屏尾部露出精选 Prompt 横向预览或信息流第一行，让用户可以直接继续浏览。
- 后续只保留分类/标签、最新/热门信息流和必要的加载/错误/空状态。
- 视觉参考华为、小米、阿里等成熟产品：单一视觉焦点、克制的字体层级、充足留白、稳定网格、明确主次按钮；不做 AI 生成式口号堆叠、渐变 Banner、玻璃装饰或卡片墙。
- 首页每一段文案都必须能对应一个实际动作或内容；无法指导操作的句子删除。

**发现/搜索 `/search`**

- 页面标题和当前筛选摘要在首屏可见。
- 搜索框、排序分段、分类/模型/标签筛选、结果总数和清除筛选。
- 列表采用稳定的 Prompt 卡片网格；桌面密集、移动单列，图片和文字不跳动。
- 空状态给出“清除筛选/返回首页/发布第一条”的下一步。

**Prompt 详情 `/prompt/:id`**

- 可保留现有圆角卡片风格，但减少装饰、增加阅读层级。
- 首屏显示封面/结果、标题、作者、模型、分类、关键统计和复制/收藏/点赞。
- 正文按结构分段：Prompt、System Prompt、Few-shot、参数、工作流说明（存在才显示）。
- 下方是评论、相关推荐、举报；评论支持登录引导、加载、分页/排序和失败重试。
- 返回按钮优先回到来源列表并恢复滚动，直接打开详情时回到发现页。

**发布 `/publish`**

- 只保留发布 Prompt 所需字段；分组为基本信息、内容、模型/参数、封面/标签、预览和提交。
- 明确草稿/提交中/成功/失败状态，防止重复提交。
- 未登录不渲染空表单，直接走安全 redirect。

**个人工作台 `/profile`、作者页 `/profile/:userId`**

- 统一作者头部、关注按钮、作品/收藏/活动分段。
- 本人视角显示编辑和退出；他人视角不显示管理动作。
- 无内容时给出创建或探索入口，不显示空白面板。

**认证页面**

- 可使用简化外壳，但仍提供 Logo、主题切换和返回入口。
- 错误、验证码、OAuth 回调和 redirect 不得破坏主题或历史记录。

## 4. 视觉与交互规范

### 4.1 色彩和密度

- 保留当前 PromptOS 色板和 `--prompt-*` 令牌；不得整套复制 NebulaSite 的樱花/深空配色。
- 浅色以暖白背景、白色表面、近黑文字为主；深色以中性深灰表面、近白文字为主。
- 主色只用于 CTA、当前状态和焦点；不要让渐变、发光或玻璃效果主导内容。
- 圆角详情卡片可以保留；列表卡片圆角不超过现有 `--prompt-radius`，避免“卡片套卡片”。
- 标题、元信息、正文有明确字号层级；不要使用负字间距和随视口缩放字体。

### 4.1.1 首页文案

- H1 使用短标语，不使用“我们致力于”“一站式”“重新定义”等 AI 常见套话。
- 首屏可见文案总量建议不超过 30 个汉字（品牌和按钮文字不计）；辅助文案最多一行。
- 一个首屏只允许一个主 CTA；第二动作使用次要按钮或文本链接，避免两个同权重的营销按钮。
- 产品定位通过“提示词”内容、搜索入口、分类和真实卡片体现，而不是靠解释段落重复声明。
- 开发完成后人工删除占位文案、英文 lorem、内部 Phase 名称和无法验证的数字。

### 4.2 超级菜单

- `SiteHeader` 在所有非回调页面渲染。
- 菜单面板必须在正常文档流中，使用 `grid-template-rows` 或 `max-height` 展开；严禁用 `position: fixed/absolute` 作为主面板，严禁全屏 backdrop。
- 支持鼠标、触摸、Enter/Space、Escape；关闭后焦点回到触发按钮。
- 展开 300–460ms，收起 180–240ms，使用非线性 easing；内容级联不能造成布局抖动。
- 菜单打开时下方内容的 `getBoundingClientRect().top` 必须下降，关闭后恢复。

### 4.3 明暗主题

- `html[data-mode="light|dark"]` 是唯一主题真相；偏好为 `system` 时跟随系统。
- `index.html` head 内联初始化脚本，阻止刷新白闪；偏好保存键固定为 `promptos-theme-mode`。
- 有 View Transitions 时，以按钮点击坐标为圆心，通过 `::view-transition-new(root)` 的 `clip-path: circle()` 扩散；不插入遮罩 DOM。
- 无 API 或 `prefers-reduced-motion` 时立即切换，功能不能依赖动画。
- `NConfigProvider`、输入框、弹层、滚动条、焦点环必须随令牌同步。

### 4.4 社区交互取舍

参考 `D:\AMP\isoumao\isoumao-web` 的频道导航、内容详情、作者信息、评论输入和返回上下文设计，但只实现 PromptOS 已有能力：Prompt 作为内容实体，评论作为讨论串，作者页作为社区身份，点赞/收藏/关注作为轻量关系。

不在本轮伪造论坛分区、动态时间线或独立帖子 API；若产品以后需要，再新增独立数据模型和契约。

## 5. 组件和数据分层

推荐目录边界：

```text
src/frontend/src/
├─ components/layout/AppShell.vue
├─ components/navigation/SiteHeader.vue
├─ components/navigation/MegaMenu.vue
├─ components/navigation/MobileMenu.vue
├─ components/navigation/ThemeToggle.vue
├─ components/navigation/BackButton.vue
├─ components/prompt/PromptCard.vue
├─ components/prompt/PromptGrid.vue
├─ components/community/CommentList.vue
├─ components/community/CommentComposer.vue
├─ components/community/AuthorSummary.vue
├─ components/feedback/PageLoading.vue
├─ components/feedback/PageError.vue
├─ composables/useSiteTheme.ts
├─ composables/useRouteTransition.ts
├─ composables/useBackNavigation.ts
├─ stores/prompt.ts
└─ styles/{tokens,transitions,main}.css
```

规则：

- View 负责页面编排，不负责重复请求、主题实现或全局导航。
- API 类型在 `src/frontend/src/types` 和 `api` 层维护；Store 负责缓存、请求竞态和互动状态。
- 所有异步页面都有 loading/error/empty/success 四种可见状态。
- 组件按钮优先使用现有 Naive UI 或 lucide（若已安装）；图标按钮必须有 `aria-label` 和 tooltip。
- 不使用无类型 `any`，不新增全局单例事件总线；跨组件只用 props/emits、Store 或明确的 DOM CustomEvent。


执行顺序：同一阶段按编号推进；跨阶段只有在依赖任务提交后才开始。每个任务一个小提交，不要把多个任务合并成一个“全部重做”提交。

默认单人/串行执行使用一个集成分支；只有并行开发或需要独立评审时才按任务拆分分支。

推荐流程：

```bash
git status --short
git switch -c codex/ui-redesign  # 已存在时改用 git switch codex/ui-redesign
# 并行任务才使用 codex/ui-redesign/<task-id>
# 实现任务；不要运行完整测试
git diff --check
git add <本任务文件>
git commit -m "<任务指定提交信息>"
git push -u origin codex/ui-redesign
```

并行任务分支则将最后一条改为 `git push -u origin codex/ui-redesign/<task-id>`，合并回集成分支后再继续下一阶段。

若仓库已有协作分支，沿用现有分支命名；不要强推，不要修改别人的提交。远端不存在或无权限时，把准确错误写入完成记录，任务标记 `[!]`，不要假装“已推送”。

## 9. 完成定义

只有同时满足以下条件，重设计才算完成：

- 首页明确定位、简洁且首屏露出真实内容；
- 所有正常页面使用同一顶部菜单和主题切换；
- MegaMenu 是文档流下推，移动端和键盘可用；
- 发现、详情、发布、作者和社区互动形成闭环；
- 明暗主题无闪烁、有圆环切换、减少动画可用；
- 没有无效入口、伪实时统计或无法解释的占位页面；
- P5 浏览器验收、自动化检查和提交推送记录全部通过。

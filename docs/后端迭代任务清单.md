# PromptOS 后端迭代任务清单

> 文档用途：将 PromptOS Go 后端下一轮迭代拆成可直接派发给其他 AI 的原子任务。
>
> 执行纪律：每个 AI 只领取一个任务或一个明确的连续任务组。实现、测试、验收全部完成后，才能把 `[ ]` 改成 `[x]`，并在任务下填写“完成记录”。禁止仅修改勾选状态，禁止以手工修改数据库状态代替代码修复。

## 0. 当前基线与本轮边界

### 0.1 当前实现

- 运行时：Go 1.25+，模块名 `promptos-backend`。
- HTTP：标准库 `net/http` + `http.ServeMux`，API 前缀 `/api/v1`。
- 数据库：MySQL 8.4，`database/sql` + `go-sql-driver/mysql`。
- 数据访问：`internal/store` 接口，包含 MySQL 实现和内存降级实现。
- 认证：自实现 HS256 JWT、bcrypt 密码、GitHub OAuth。
- 存储：本地文件系统或 Cloudflare R2。
- Redis：Compose 已启动 Redis 7，但业务代码尚未建立客户端或使用场景。
- 已有功能：注册、登录、密码重置、资料、关注、Prompt 增删改查、搜索、草稿、点赞、收藏、浏览记录、评论、举报、上传。
- 已有测试：JWT、验证码、响应信封、内存 store、部分 MySQL scan、迁移 SQL 拆分、校验与内容审核单元测试。

### 0.2 已确认的工程问题

1. 全新数据库启动时，`0002_fix_seed_text_encoding.sql` 会在 Prompt 种子插入前写 `prompt_tags`，触发外键错误；随后后端静默回退到内存 store。
2. `schema.sql` 已包含部分迁移字段，而迁移仍无条件 `ADD COLUMN`，例如 `0008_prompt_images.sql` 会出现重复列错误。
3. API 层先从 MySQL 读取全部 Prompt，再在 Go 中分页；数据量增长后会造成不必要的查询、内存和序列化成本。
4. `GET /api/v1/categories` 使用静态内存分类，Prompt MySQL 写入前也使用静态分类校验，数据库分类和代码分类可能漂移。
5. Redis 仅存在于 Compose；验证码和 OAuth state 仍保存在单进程内存中，扩容或重启会丢失。
6. `POST /api/v1/user/logout` 没有真正使当前 JWT 失效；GitHub OAuth 回调把 JWT 放进 URL query，可能进入历史记录、日志和 Referer。
7. 默认 JWT 密钥和 MySQL root 密码适合演示，不适合非开发环境；配置加载没有强校验。
8. HTTP Server 只有 `ReadHeaderTimeout`，缺少 `ReadTimeout`、`WriteTimeout`、`IdleTimeout`、优雅退出和统一请求体大小限制。
9. JSON decoder 没有 `DisallowUnknownFields`，大多数错误响应缺少稳定错误标识，客户端只能比较英文 message。
10. 上传只读取后检查 MIME；未先用 `http.MaxBytesReader` 限制整个 multipart 请求，也未校验图片尺寸、解码有效性和资源归属。
11. 健康接口只报告进程状态和当前 store 模式，不能区分 liveness、readiness、MySQL/Redis 故障及降级原因。
12. 现有测试以单元测试为主，缺少真实 MySQL/Redis、完整 HTTP handler 和全新数据库迁移集成测试。

### 0.3 本轮目标

1. 全新数据库和已有数据库均可重复、可审计地完成迁移，启动后稳定使用 MySQL。
2. API 有一致的参数校验、分页、错误码、请求追踪、超时和安全头。
3. 登录、登出、验证码和 GitHub OAuth 达到可部署的基础安全水平。
4. Prompt、评论、互动计数和上传在并发及失败条件下保持一致。
5. Redis 只接入明确有收益的能力，不为了“用了 Redis”而引入无效复杂度。
6. 通过单元测试、HTTP 集成测试、数据库迁移测试和 Docker 健康检查形成交付闭环。

### 0.4 不在本轮范围

- 不引入 Spring/Java、微服务拆分、RabbitMQ、Kafka、ElasticSearch、Kubernetes。
- 不提前实现 Phase 2 的 Skill 执行、Playground、Agent、Workflow 引擎。
- 不提前实现 Phase 3 的支付、企业组织、管理后台。
- 不在没有实际查询证据时引入 ORM 或整套 Web 框架。

- [ ] 派发给 AI：OAuth state 存 Redis 并单次消费，cookie 在 HTTPS 生产环境设置 `Secure`、`HttpOnly`、`SameSite=Lax`，回调校验 state、cookie、TTL。

### B3-05 登录、注册和密码重置防滥用

- [ ] 派发给 AI：使用 Redis 实现登录、注册、验证码、密码重置的分级限流；key 组合考虑 IP 和标准化邮箱，避免仅靠单一维度误伤或绕过。

## 12. Go 文件夹、命名、分层和注释规范

### 12.1 推荐目录

```text
src/backend/
├─ cmd/api/                 # 进程入口、信号和生命周期装配
├─ internal/
│  ├─ api/                  # 路由、middleware、HTTP DTO/handler
│  ├─ auth/                 # token claims、签发和验证
│  ├─ cache/                # Redis 客户端与领域无关缓存原语
│  ├─ config/               # 环境配置加载与校验
│  ├─ database/             # MySQL 连接和迁移执行
│  ├─ service/              # 仅放跨 store/cache 的业务编排
│  ├─ storage/              # local/R2 对象存储
│  └─ store/                # 领域模型、接口、MySQL/内存实现
└─ sql/
   ├─ migrations/           # 不可变的顺序增量迁移
   └─ schema.sql            # 明确用途的全新库基线
```

只有任务确实需要时才创建 `cache/`、`service/`，禁止提前生成空目录和空接口。

### 12.2 命名

- 包名小写单词，不使用下划线：`package storage`、`package config`。
- Go 文件名使用 snake_case：`prompt_handlers.go`、`mysql_prompts.go`、`request_id.go`。
- 导出类型表达领域职责：`PromptStore`、`AuthService`；避免 `Manager2`、`CommonUtil`、`Helper`。
- HTTP 输入/输出 DTO 保留在 `internal/api`，领域输入留在 `store`/`service`，不要让 JSON tag 类型渗透所有层。
- sentinel error 使用 `ErrPromptNotFound`；需要附上下文时用 `%w`，禁止依赖 `err.Error()` 字符串分支。
- 配置环境变量继续大写下划线；新增变量同步更新 `.env.docker.example` 和 README。

### 12.3 分层规则

- `cmd/api` 只装配依赖、启动和退出，不写业务。
- `api` 不写 SQL，不直接依赖具体 MySQL struct，面向接口调用。
- `service` 负责跨资源事务语义、缓存失效、会话策略；不处理 `http.ResponseWriter`。
- `store` 负责持久化和领域数据映射；事务边界要清楚，所有 rows 必须关闭并检查 `rows.Err()`。
- `cache` 提供 Redis 原语或窄接口；不要在每个 handler 创建客户端。
- `storage` 不依赖 HTTP handler；对象键、安全校验和 provider 错误可测试。
- context 从请求一路向下传递；禁止用 `context.Background()` 替代请求 context 执行业务操作，启动初始化除外。

### 12.4 注释和日志

- 注释使用英文，解释约束、并发、不变量和安全原因，不复述语法。
- 所有导出标识符按 Go lint 习惯写 doc comment；内部直观函数不强行写空洞注释。
- 迁移文件顶部用英文说明目的、兼容前置版本和不可逆影响。
- TODO 格式：`// TODO(owner: backend): remove compatibility path after migration 0012 is deployed.`
- 禁止 `fmt.Println` 调试日志进入提交；统一结构化 logger。
- 禁止日志记录 JWT、密码、验证码、OAuth code、R2/MySQL/Redis 密钥和完整请求正文。

### 12.5 数据库规范

- 所有新表使用 `utf8mb4`、明确主键、必要索引、created/updated 时间语义。
- 外键是否使用必须保持一致；若保留外键，迁移/种子顺序必须满足约束，不能靠临时关闭检查掩盖问题。
- 计数明细双写必须在事务内；高并发计数先保证正确，再考虑异步化。
- 查询新增索引前必须看 `EXPLAIN`；不要重复建等价索引。
- 禁止字符串拼接用户输入生成 SQL；动态表名/列名只能来自代码内白名单。

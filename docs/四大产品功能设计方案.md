# PromptOS 四大产品功能设计方案与用户端需求规划

> 版本 v1.0（2026-09-05）。对应完整迭代 TODO 风险表中"Skill 运行器、在线
> Playground、创作者学院、提示词交易市场尚未实现"一项；本文即 TODO 所要求的
> "需求、执行沙箱、计费和内容审核方案"。评审通过后进入开发，按里程碑分期
> 交付；每功能独立能力开关（`capabilities.ts` 已就位），未达上线门槛不开放。

## 0. 设计原则（跨功能）

1. **复用现有地基**：能力开关（F-06）、内容安全校验（S-08）、分维度限流
   （S-07）、举报与审计闭环（S-14）、RustFS 对象存储（D-12/D-13）、契约测试
   （A-05）、管理控制台。新功能不新建第二套治理体系。
2. **开关灰度**：每个功能独立构建期开关 + 运行期白名单
   （`user_roles` 扩展 `role='beta'`），先内测后全量；关闭时保持现状的
   "即将开放"禁用态，不出现半成品入口。
3. **不自制危险能力**：Skill 托管执行与 Playground 共用同一个**受控执行层**，
   首选"模型网关 + 参数化运行"，代码级沙箱放最后阶段。
4. **成本可视**：所有调用 LLM 的功能必须有配额、超时与用量记录，无上限的
   功能不允许上线。

## 1. 用户端需求规划（跨功能）

### 1.1 角色与权限矩阵

| 能力 | 匿名访客 | 注册用户 | 创作者（beta/认证） | 管理员 |
|---|---|---|---|---|
| 浏览 Skill / 学院 / 市场列表 | ✅ | ✅ | ✅ | ✅ |
| Playground 试用 | 每日 3 次 | 每日 20 次 | 每日 100 次 | 不限 |
| 运行 Skill（引导式） | — | ✅ | ✅ | ✅ |
| 运行 Skill（托管执行） | — | 每日 5 次 | 每日 30 次 | 不限 |
| 发布 / 上架 | — | ✅（市场需创作者） | ✅ | ✅ |
| 购买市场提示词 | — | ✅ | ✅ | ✅ |
| 学院学习进度 | — | ✅ | ✅ | ✅ |
| 内容审核 / 审计链 | — | — | — | ✅ |

创作者准入：注册用户在控制台申请 → 管理员在审核控制台批准
（`user_roles` 增加 `role='creator'`）→ 获得上架/发布资格。

### 1.2 用户故事地图（按旅程）

- **发现**：作为访客，我想在导航中看到四大能力的入口与介绍页，明白"是什么、
  对我有什么用"，未被授权的功能点击后看到清晰的解锁条件。
- **试用**：作为访客，我能在 Playground 免费体验 3 次，被引导注册以获得更多次数。
- **创作**：作为注册用户，我能把提示词结构化为 Skill（步骤 + 输入输出），
  一步步跟随引导执行并保存运行记录。
- **学习**：作为新用户，我在学院按路径学习并通过"复制到 Playground 立即试"
  的联动快速获得正反馈。
- **变现**：作为创作者，我把打磨成熟的提示词上架市场，设定价格，看到订单与
  收益；作为买家，我购买后能在"我的已购"中随时使用。
- **治理**：作为管理员，我在既有审核控制台处理学院/市场的举报与上架审核，
  审计链可追溯。

### 1.3 页面路由规划（前端，全部挂能力开关）

| 路由 | 功能 | 开关 |
|---|---|---|
| `/skills` `/skills/:id` `/skills/:id/run` | Skill 列表/详情/运行 | `skillRunner` |
| `/playground` | Playground | `playground` |
| `/academy` `/academy/:slug` | 学院列表/文章 | `creatorAcademy` |
| `/market` `/market/:promptId` `/market/orders` `/market/creator` | 市场/详情/我的订单/创作者工作台 | `marketplace` |

MegaMenu 现有禁用入口在这些开关为 true 时点亮，并链接到上述路由。

### 1.4 分期路线图

| 里程碑 | 内容 | 上线门槛 |
|---|---|---|
| **M1 体验闭环**（可先行开发） | Playground（接模型网关、匿名配额）、Skill 引导式运行、学院阅读 MVP、市场浏览 + 兑换码兑换 | 单测/契约/E2E 全绿；滥用限流与成本上限生效；开关默认 off，白名单内测 |
| **M2 商业化前置** | Skill 托管沙箱执行、创作者体系（申请/批准）、市场订单与支付对接 | 沙箱安全评审；支付商户资质（外部前置）；人审流程在管理控制台可用 |
| **M3 规模化** | 分成结算与提现、学习路径/证书、市场推荐与搜索增强 | 结算对账证据；法务合规复核 |

## 2. Skill 运行器

### 2.1 产品定位与用户端需求

把社区里的"结构化提示词工作流"变成**可复用的运行工具**：Skill = 步骤化
工作流（现有 `skills.workflow` JSON）+ 输入输出模式（`io_schema`）。

用户端需求：
- 我可以浏览/搜索 Skill，看步骤图与输入说明；
- 点"运行"后，按 `io_schema` 渲染参数表单（文本/选择/文件引用）；
- **引导式运行（M1）**：逐步骤展示提示词模板，一键复制到我的 AI 工具，
  每步可粘贴回执/备注，全部完成后生成"运行报告"可保存与分享；
- **托管执行（M2）**：服务端调用模型网关自动执行各步骤并汇总输出；
- 我可以查看自己的运行历史（入参 + 输出 + 时间），重新运行；
- 作者可以基于自己已发布的 Prompt 一键创建 Skill。

### 2.2 执行层设计（与 Playground 共用）

- **模型网关**：后端新增内部服务 `runner`，OpenAI 兼容协议适配器；
  模型供应商密钥只在服务端（`app.env`：`LLM_API_KEY` 等，绝不入前端）。
- **托管沙箱（M2）边界**：只执行"提示词编排"而非任意代码——步骤模板 +
  用户输入 → 网关调用；**不引入通用代码执行**。若未来需要代码解释器，
  使用一次性容器：无网络、只读根文件系统、CPU/内存/时长限额、输出上限，
  且作为独立决策再评审。
- **超时与重试**：单步 60s、整次 5 分钟上限；失败可重试（重新计配额）。

### 2.3 API 契约草案（进入 `api-contract.schema.json`）

```
GET    /api/v1/skills?keyword=&page=        列表（公开，status=1）
GET    /api/v1/skills/{id}                  详情（含 workflow/io_schema）
POST   /api/v1/skills                       创建/发布（创作者，过 S-08 校验）
PUT    /api/v1/skills/{id}                  更新（作者）
DELETE /api/v1/skills/{id}                  删除（软删 status=-1）
POST   /api/v1/skills/{id}/runs             创建运行（M1 引导式：仅登记；
                                            M2：触发托管执行，返回 runId）
GET    /api/v1/skills/runs/{runId}          运行详情（作者本人或管理员）
GET    /api/v1/user/skill-runs?page=        我的运行历史
```

### 2.4 数据模型

```sql
CREATE TABLE skill_runs (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  skill_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  mode ENUM('guided','hosted') NOT NULL,
  inputs JSON NOT NULL,
  steps JSON NULL,          -- 引导式：各步骤回执
  output JSON NULL,         -- 托管式：模型输出
  status ENUM('running','done','failed','expired') NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_time (user_id, created_at),
  INDEX idx_skill (skill_id),
  FOREIGN KEY (skill_id) REFERENCES skills(id),
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### 2.5 治理与计费

- 上架与编辑过 S-08 内容校验；举报复用现有 reports 闭环（targetType 扩展
  `skill`），管理控制台处置复用 `setTargetStatus`。
- 配额：见 1.1 矩阵；用量计数进统一配额表（Redis 计数 + 每日落库）。
- 托管执行按次计配额，M2 起按 token 计量（仅计量不计费，计费在市场）。

## 3. 在线 Playground

### 3.1 产品定位与用户端需求

"先试后用"的即时体验场：选择任意公开提示词（或空白模板）→ 填变量 →
调参数（temperature/top_p/max_tokens）→ 流式查看输出 → 一键复制或保存为
草稿。对社区的意义：提升 Prompt 详情的转化率（详情页增加"在 Playground
中打开"）。

用户端需求：
- 匿名可用（每日 3 次），注册后 20 次/日——注册转化钩子；
- 模型选择（首发 2-3 个稳定模型）、参数滑杆与预设（创意/均衡/精确）；
- 流式输出（SSE）、停止按钮、失败重试；
- 会话内历史（刷新不丢）、复制输出、把满意结果保存为草稿提示词；
- 敏感内容拦截提示；配额用尽时展示注册/明日再试引导。

### 3.2 技术设计

- `POST /api/v1/playground/run`（SSE 流式响应）：服务端组装系统提示 +
  用户输入 → 网关转发；服务端持密钥，前端只见流式文本。
- 配额与滥用：Redis 计数（匿名按 IP + 指纹，登录按用户）；单次输出上限
  4k tokens；单用户每日 token 上限；全站每日成本熔断（超出自动降配额并告警
  到 `promptos-alert.sh` 通道）。
- **不保存**匿名会话内容（隐私）；登录用户的会话历史本地存储（localStorage），
  明确标注"不上云"。
- 审计：仅记录用量计数（用户/时长/tokens），不记录提示词内容——规避内容
  存储合规负担；若未来需要滥用回溯，走举报+管理员人工路径。

## 4. 创作者学院

### 4.1 产品定位与用户端需求

官方 + 认证创作者的教学内容（怎么写好提示词、工作流拆解、案例复盘），
提升社区整体质量并为市场培养供给。

用户端需求：
- 访客可浏览与阅读全部文章（SEO 友好的 SSR/预渲染路径，M1 用现有 SPA + meta）；
- 文章关联提示词：阅读中一键"复制提示词"或"在 Playground 打开"；
- 登录用户有学习进度（已读标记，M1 仅本人可见）；
- 创作者在专门表单发文（Markdown，走 S-08 校验），管理员审核后发布；
- 分类：入门 / 提示词技巧 / 工作流拆解 / 案例复盘。

### 4.2 数据与契约草案

```sql
CREATE TABLE academy_articles (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  slug VARCHAR(120) NOT NULL UNIQUE,
  title VARCHAR(200) NOT NULL,
  summary VARCHAR(500) DEFAULT '',
  content_md MEDIUMTEXT NOT NULL,
  category ENUM('basics','technique','workflow','case') NOT NULL,
  author_id BIGINT NOT NULL,
  status ENUM('draft','in_review','published','offline') NOT NULL DEFAULT 'draft',
  views INT DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FULLTEXT idx_title_summary (title, summary),
  FOREIGN KEY (author_id) REFERENCES users(id)
);
```

契约：`GET /academy/articles?category=&page=`、`GET /academy/articles/{slug}`、
`POST/PUT /academy/articles`（创作者）、`PATCH /admin/academy/{id}`
（审核发布/下线，入审计链）。学习进度：`PUT /user/academy/progress`。

### 4.3 治理

发文走"草稿 → in_review → 管理控制台审核 → 发布"，全程审计；举报复用
现有闭环（targetType 扩展 `article`）。

## 5. 提示词交易市场

### 5.1 产品定位与用户端需求

创作者把成熟提示词**定价出售**；买家付费获得完整内容与后续更新访问权。
平台提供审核、担保与结算。

用户端需求：
- **创作者**：从"我的提示词"一键上架 → 定价（阶梯：¥9.9/¥19.9/¥39.9 或自定义）
  → 提交审核 → 审核通过后上架；查看浏览/订单/收益看板；下架与改价；
- **买家**：浏览市场（分类/排序/销量）、查看公开摘要与评价 → 购买 → 内容
  解锁并出现在"我的已购"；重复购买幂等；
- **纠纷**：买家可对已购内容发起举报（复用 reports），管理员可退款
  （订单状态 refunded + 审计）。

### 5.2 计费与支付设计（分两阶段，外部前置明确）

| 阶段 | 方案 | 前置条件 |
|---|---|---|
| M1 兑换码 | 管理员生成兑换码（对应某 listing 或通用额度），用户兑换解锁 | 无支付通道依赖，先行验证需求 |
| M2 在线支付 | 微信支付/支付宝 NATIVE 扫码，服务端回调加单；平台分成 20%（可议），结算周期 T+7 | 商户资质、实名主体（外部前置） |

### 5.3 数据模型

```sql
CREATE TABLE market_listings (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  prompt_id BIGINT NOT NULL,
  creator_id BIGINT NOT NULL,
  price_cents INT NOT NULL CHECK (price_cents >= 100),
  status ENUM('in_review','on_sale','offline') NOT NULL DEFAULT 'in_review',
  sales INT DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uq_prompt (prompt_id),
  FOREIGN KEY (prompt_id) REFERENCES prompts(id),
  FOREIGN KEY (creator_id) REFERENCES users(id)
);

CREATE TABLE market_orders (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  listing_id BIGINT NOT NULL,
  buyer_id BIGINT NOT NULL,
  amount_cents INT NOT NULL,
  status ENUM('pending','paid','refunded','cancelled') NOT NULL,
  payment_ref VARCHAR(128) NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  paid_at TIMESTAMP NULL,
  UNIQUE KEY uq_listing_buyer_paid (listing_id, buyer_id, status),
  FOREIGN KEY (listing_id) REFERENCES market_listings(id),
  FOREIGN KEY (buyer_id) REFERENCES users(id)
);
```

已购访问控制：后端在返回提示词详情时检查"有效 paid 订单 OR 作者"，未购买
仅返回摘要 + 预览段（首 200 字 + 结构目录）。

### 5.4 风险与对策

- **版权**：上架协议要求原创承诺 + 举报下架通道；重复内容检测（与现有
  prompts 指纹比对，M2）。
- **套利/退款滥用**：退款仅管理员裁决并审计；退款后收回访问权（订单状态
  驱动）。
- **刷单**：同一支付账号/用户维度的购买频率限流；销量排序使用时间衰减。

## 7. 开放问题（需产品决策）

1. Playground 首发接入哪 1-3 个模型供应商（涉及成本与内容安全差异）？
2. 市场分成比例与定价指导（本文建议 20% 起议）。
3. 创作者准入是否需要实名/保证金（影响 M2 排期）。
4. Skill 托管执行是否引入第三方代码解释器服务（替代自建沙箱）。

> 以上任何一项确定后，按本文契约草案进入开发；开关保持 off 直到
> 第 6 节门槛逐项通过。

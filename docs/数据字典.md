# PromptOS 数据字典

更新时间：2026-09-04

本文与 `src/backend/sql/schema.sql` 及已编号迁移保持一致。字段类型以 MySQL 8.4 为准；生产变更必须新增迁移，不直接修改已执行文件。

## 约定

- 主键均为自增 `BIGINT`，应用层当前使用 `int` 读取 ID。
- 时间字段由 MySQL UTC 连接或应用 UTC 写入；接口统一输出 RFC3339 或日期字符串。
- Prompt/Skill 状态：`1=published`、`0=draft`、`-1=deleted`。公开读取必须同时满足目标已发布、作者 `users.status=1`。
- 用户状态：`1=active`、`0=disabled`；禁用用户的公开内容不再可见，历史数据不物理删除。
- 多态目标只允许代码枚举：`prompt`、`skill`、`comment`（不同表的允许集合见下表）。数据库无法为多态 ID 建立单一外键，写入路径必须先校验，审计任务必须扫描孤儿行。
- 上传状态：`pending`、`referenced`、`trashed`；回收任务只处理超过保留期的 `pending/trashed` 对象。

## 表与字段

### `users`

| 字段 | 类型/空值 | 语义 |
|---|---|---|
| `id` | BIGINT PK | 用户 ID |
| `username` | VARCHAR(39) UNIQUE | 展示名/登录标识，应用层校验长度和控制字符 |
| `avatar` | VARCHAR(500) NULL | 头像 URL 或本地上传路径 |
| `email` | VARCHAR(100) UNIQUE | 私有账号邮箱，不进入公开 DTO |
| `github_id` | BIGINT NULL UNIQUE | GitHub 绑定 ID |
| `password` | VARCHAR(100) NULL | 密码哈希；OAuth/官方账号可为空 |
| `bio` | VARCHAR(500) NULL | 个人简介 |
| `level` / `experience` | INT | 等级与经验值 |
| `session_version` | INT NOT NULL | 递增后撤销旧 JWT |
| `status` | INT | `1 active` / `0 disabled` |
| `created_at` / `updated_at` | TIMESTAMP | 创建和更新时间 |

关键索引：`idx_email`、`idx_username`、`idx_github_id`。

### `categories`

`id`、`name VARCHAR(50)`、`icon VARCHAR(100)`、`sort INT`、`type INT`、`created_at`。`type=1` 为 Prompt 分类，`type=2` 为 Skill 分类；列表只读取对应类型并按 `sort,id` 排序。

### `prompts`

| 字段 | 类型/空值 | 语义 |
|---|---|---|
| `id` | BIGINT PK | Prompt ID |
| `title` / `description` | VARCHAR(200/1000) | 标题和描述 |
| `cover` | VARCHAR(1024) | 封面 URL/上传路径 |
| `images` | JSON NULL | 结果图 URL 数组 |
| `content` | TEXT | 用户可复制的 Prompt 内容 |
| `system_prompt` | VARCHAR(2000) | 系统 Prompt |
| `model` | VARCHAR(50) | 目标模型 |
| `params` | JSON NULL | 模型参数对象 |
| `category_id` / `user_id` | BIGINT FK | 分类和作者；分别引用 `categories.id`、`users.id` |
| `views` / `likes` / `favorites` | INT | 与明细表同步的汇总计数 |
| `status` | INT | `1/0/-1` 发布/草稿/删除 |
| `created_at` / `updated_at` | TIMESTAMP | 生命周期时间 |

关键索引：`idx_status_category_created`、`idx_user_created`、`idx_status_popular`；公开列表必须带 `status=1` 和作者启用条件。

### `skills`

`id`、`name`、`description`、`cover`、`workflow JSON`、`io_schema JSON`、`user_id FK`、`views/likes/favorites`、`status`、`created_at`、`updated_at`。当前 API 尚未开放 Skill 写入，预留多态目标使用。

### `prompt_tags`

`id`、`prompt_id BIGINT FK ... ON DELETE CASCADE`、`tag VARCHAR(50)`。唯一键 `uk_prompt_tag(prompt_id,tag)`；应用层和 `0015_normalize_prompt_tags.sql` 负责 trim、合并空白、大小写规范、长度限制和去重。

### `comments`

`id`、`target_type`（当前只写 `prompt`，预留 `skill`）、`target_id`、`user_id FK`、`content VARCHAR(1000)`、`parent_id FK ... ON DELETE CASCADE`、`likes`、`created_at`。根评论分页索引为 `idx_target_parent_created` 和 `idx_target_parent_likes`；回复通过 `parent_id` 组树。

### `favorites`

`id`、`user_id FK`、`target_type`（`prompt|skill`）、`target_id`、`created_at`。唯一键 `uk_user_target(user_id,target_type,target_id)`，用于幂等收藏。

### `likes`

`id`、`user_id FK`、`target_type`（`prompt|skill|comment`）、`target_id`、`created_at`。唯一键 `uk_user_target`，用于幂等点赞；Prompt/评论汇总计数必须与明细一致。

### `reports`

`id`、`user_id FK`、`target_type`（`prompt|skill|comment`）、`target_id`、`reason VARCHAR(80)`、`detail VARCHAR(500)`、`status`（`pending|reviewed|rejected`）、`created_at`、`updated_at`。同一用户对同一目标唯一一条待处理/历史记录。

### `view_histories`

`id`、`user_id FK`、`prompt_id FK ... ON DELETE CASCADE`、`viewed_at`、`created_at`、`updated_at`。唯一键 `uk_user_prompt` 保证登录用户重复浏览只更新时间；匿名浏览不写该表。

### `follows`

`id`、`follower_id FK`、`following_id FK`、`created_at`。唯一键 `uk_follow`，应用层拒绝自己关注。

### `uploads`

`id`、`owner_id BIGINT FK ... ON DELETE RESTRICT`、`provider`、`purpose`（`prompt_image|avatar`）、`object_key UNIQUE`、`content_type`、`size`、`status`、`created_at`、`updated_at`。对象本体当前在独立 Docker 卷；迁移到 PromptOS 专用 RustFS bucket 前不得删除原卷。

## 保留与删除

| 数据 | 当前规则 | 物理删除条件 |
|---|---|---|
| 用户 | 禁用并递增 `session_version`；公开内容隐藏 | 注销流程和备份确认后，按法务/运营保留期执行 |
| Prompt/Skill | `status=-1` 软删，审计和历史保留 | 完成导出、备份和对象引用审计后 |
| 评论 | 无独立软删字段；删除目标或父评论级联子回复 | 目标生命周期清理时级联 |
| 点赞/收藏/关注/举报 | 唯一键幂等；目标删除后由审计任务清理孤儿 | 审核留存期结束或目标已删除 |
| 浏览历史 | 用户可清除；Prompt 删除级联 | 用户主动清除或保留期结束 |
| 上传 | `pending -> referenced -> trashed`，延迟回收 | 对象和数据库记录均校验无引用后 |

## 迁移与审计

- 迁移按 `src/backend/sql/migrations/README.md` 的数字顺序执行，并写入 `schema_migrations`。
- 计数漂移使用 `0012_recalibrate_counters.sql` 修复；标签历史数据使用 `0015_normalize_prompt_tags.sql` 修复。
- 多态目标、计数、上传引用和备份完整性属于后台审计范围；审计失败必须告警，不得静默删除数据。

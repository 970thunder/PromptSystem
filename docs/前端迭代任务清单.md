# PromptOS 前端迭代任务清单

> 文档用途：将 PromptOS 的下一轮迭代拆成可以直接派发给其他 AI 的工程任务。
> 
> 执行规则：AI 每完成一个任务，必须先完成该任务的验收项，再把对应的 `[ ]` 改为 `[x]`，并在任务下补充“完成记录”。禁止只改勾选状态而不验证。
>
> 后端配套任务：统一见 `docs/后端迭代任务清单.md`。本文件第 8 节只保留影响前端联调的摘要，实际后端实现和验收以后端清单为准。

## 0. 项目基线与目标

### 0.1 当前项目事实

- 前端位于 `src/frontend/`，技术栈为 Vue 3、TypeScript、Vite、TailwindCSS、Pinia、Vue Router 4、Naive UI、Axios。
- 页面目前主要由 `HomeView.vue`、`SearchView.vue`、`PromptDetailView.vue`、`PublishView.vue`、`ProfileView.vue`、登录注册页面组成。
- 首页已经有 Prompt 信息流、分类筛选、热门标签、精选卡片和发布入口，但首屏没有清楚回答“PromptOS 是什么、用户可以做什么、下一步应该点击哪里”。
- 当前全局样式大量使用硬编码浅色值，`App.vue` 的 Naive UI 主题也固定为浅色；没有统一的主题状态、主题防闪烁初始化和明暗切换动画。
- 多个页面各自实现“返回首页”，返回行为没有统一处理浏览器历史、直接打开页面、登录重定向和滚动位置。
- 首页导航中的 `/search?tab=workflow`、`/search?tab=agent` 目前没有对应的筛选解析，属于需要补齐的功能路径。
- 首页统计中的“320+”“1.8k”等值是硬编码演示数据；必须标注演示性质或改为真实接口数据，不能伪装成真实社区统计。
- 前端生产构建和 ESLint 检查已经通过；Docker Compose 前端、后端、MySQL、Redis 已可启动。后端初始化曾出现迁移顺序问题，见第 7 节。

### 0.2 本轮产品目标

1. 用户打开首页后，在首屏内理解 PromptOS 是“可发现、拆解、收藏、发布和复用 AI 提示词的社区平台”。
2. 用户能从首页自然进入发现、搜索、Prompt 详情、发布和个人工作台，不需要猜导航含义。
3. 顶部超级菜单展开时必须在正常文档流中把下面内容向下推开，不能用绝对定位的浮层或全屏遮罩伪装成“下推菜单”。
4. 页面切换、主题切换、列表增删和菜单开合都使用有方向、有节奏的非线性过渡；返回操作的动画方向必须与前进相反。
5. 明暗主题的实现与 NebulaSite 的核心机制对齐：`html[data-mode]`、原生 View Transitions、以点击点为圆心的 `clip-path` 圆环扩散，不插入遮罩层。
6. 在不提前实现 Phase 2 Skill 运行器、Playground 或 Phase 3 商业化功能的前提下，补齐当前 MVP 的体验缺口、可访问性、加载状态和性能问题。

### P2-02 实现无遮罩的圆环扩散主题切换

- [ ] 派发给 AI：在 `useSiteTheme.ts` 中实现以下与 NebulaSite 对齐的机制：

```ts
type ThemeDocument = Document & {
  startViewTransition?: (update: () => void | Promise<void>) => {
    ready: Promise<void>
    finished: Promise<void>
  }
}

function switchTheme(event: MouseEvent | undefined, apply: () => void) {
  const doc = document as ThemeDocument
  const root = document.documentElement
  const reduceMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches

  if (!event || reduceMotion || !doc.startViewTransition) {
    apply()
    return
  }

  const x = event.clientX
  const y = event.clientY
  const radius = Math.hypot(
    Math.max(x, window.innerWidth - x),
    Math.max(y, window.innerHeight - y),
  )
  const transition = doc.startViewTransition(async () => {
    apply()
    await Promise.resolve()
  })

  void transition.ready.then(() => root.animate(
    {
      clipPath: [
        `circle(0px at ${x}px ${y}px)`,
        `circle(${radius}px at ${x}px ${y}px)`,
      ],
    },
    {
      duration: 460,
      easing: 'cubic-bezier(.22, 1, .36, 1)',
      pseudoElement: '::view-transition-new(root)',
    },
  ))
}
```

- 必须配套 CSS：`::view-transition-old(root)` 和 `::view-transition-new(root)` 关闭默认动画，new root 位于上层；动画结束后清理临时 class/状态。
- 严禁新增 `position: fixed; inset: 0` 的 theme mask、`theme-overlay`、`theme-reveal` DOM 节点或用一张半透明色块盖住页面。允许使用浏览器的 `::view-transition-new(root)` 伪元素，因为它不是应用 DOM 遮罩。
- 点击图标应以实际点击坐标为圆心；键盘触发或无坐标时采用视口中心并保持可用。
- 验收：点击切换时能看到从点击点扩散的圆环；检查 DOM 没有主题遮罩节点；无 View Transition 的浏览器也能正常切换；`prefers-reduced-motion` 下不执行大范围动画。

### P2-03 统一组件和元素过渡

- [ ] 派发给 AI：新增 `src/frontend/src/styles/transitions.css`，统一动效令牌和过渡类，应用于菜单、按钮、卡片、筛选、骨架屏、列表增删和主题颜色变化。
- 颜色、边框、阴影使用短过渡；进入/离开使用 transform + opacity；列表使用 Vue `TransitionGroup` 并提供稳定 key；禁止用 `transition: all` 造成不可控布局动画。
- 必须使用非线性 easing：进入 `cubic-bezier(0.16, 1, 0.3, 1)`，离开 `cubic-bezier(0.4, 0, 1, 1)`，列表移动使用同一 ease-out；不允许所有元素同时弹跳或无限循环动画。
- `@media (prefers-reduced-motion: reduce)` 将持续动画、位移和大范围缩放降级为极短或无动画，但仍保留状态变化和焦点可见性。
- 验收：全局搜索新增交互样式没有线性 `ease` 作为主要进入动画；按钮 hover/focus、菜单开合、卡片列表变化都有稳定、不抖动的效果。

## 5. P3 - 页面切换、返回和滚动逻辑

### P3-01 建立带方向的路由过渡

- [ ] 派发给 AI：在 `App.vue` 用 Vue `<Transition>` 包裹 `<RouterView>`，或在 `AppShell.vue` 内完成；新增 `useRouteTransition.ts` 计算 `forward/back/replace`。
- 前进方向：旧页面向左退出，新页面从右侧进入；返回方向：旧页面向右退出，新页面从左侧进入；替换/筛选 query 变化不应产生夸张的横向推拉，使用轻量 fade/raise。
- 推荐令牌：forward enter `translate3d(34px,0,0) rotate(.6deg)` 到原位，leave 到 `translate3d(-26px,0,0) rotate(-.4deg)`；back 方向完全反转。进入使用 360-440ms ease-out，离开 180-240ms ease-in。
- 不要只写一个无方向的 `fade`，也不要同时保留多个嵌套 Transition 导致动画叠加。
- 验收：`首页 -> 搜索 -> 详情` 为前进方向；浏览器返回和统一返回按钮为反向；query 筛选只替换内容，不触发错误方向；减少动效设置下没有大位移。

### P3-02 统一 BackButton 和外部进入兜底

- [ ] 派发给 AI：新增 `BackButton.vue` 和 `useBackNavigation.ts`。
- 规则：有同源历史且来源属于 PromptOS 时调用 `router.back()`；没有可安全返回的历史、用户从新标签页直接打开详情、或来源为外站时跳转到指定 fallback（默认 `/`）。
- `BackButton` 必须支持 `fallback`、`label`、`aria-label`；详情页 fallback 为 `/`，搜索页 fallback 为 `/`，发布页 fallback 为 `/profile` 或 `/`（根据当前用户状态）。
- 登录拦截后的 `redirect` 必须只接受站内路径，登录成功后返回原目标；非法或循环 redirect 一律回首页。
- 验收：直接打开 `/prompt/105`、从首页进入 `/prompt/105`、登录后进入 `/publish` 三种场景的返回都正确；不会回到登录页循环。

## 10. 文件夹、命名、分层和注释规范

### 10.1 文件夹与命名

- Vue 组件使用 PascalCase：`SiteHeader.vue`、`PromptCard.vue`、`BackButton.vue`。
- TypeScript 文件使用 camelCase：`useSiteTheme.ts`、`useRouteTransition.ts`、`promptApi.ts`。
- 页面文件放 `src/frontend/src/views/`，可复用组件放 `components/`，状态放 `stores/`，接口放 `api/`，类型放 `types/`，可复用逻辑放 `composables/`，纯函数放 `utils/`。
- 组件按职责分子目录：`layout/`、`navigation/`、`prompt/`、`feedback/`。不要新建 `common2/`、`temp/`、`misc/` 等无法表达职责的目录。
- CSS 类名使用 kebab-case，并按组件前缀分组，例如 `.prompt-card__title`、`.site-header--expanded`。不要用随机颜色名或页面无关的 `.box1`。
- 文档放 `docs/`；中文产品文档使用中文文件名，代码和 API 标识保持英文。

### 10.2 分层边界

- View：组合页面结构、调用 store/composable、处理页面级交互；不写通用主题引擎，不复制站点 Header。
- Component：展示和局部交互，通过 props/emits 接收数据；不直接拼接 API URL，不直接操作多个页面的路由状态。
- Store：跨页面业务状态和 API 数据缓存；不放 DOM 动画和元素查询。
- Composable：可复用的主题、路由历史、菜单焦点、媒体查询逻辑；必须有明确输入/输出类型。
- API：只负责请求和响应类型，不把 fallback mock、UI 提示和路由跳转混在一起。
- Utils：纯函数优先，无副作用；涉及浏览器 API 的函数要明确 client-only 使用条件。
- CSS：主题颜色来自令牌；动画来自统一令牌；禁止在单个页面重新定义一套全局主题。

### 10.3 注释规范

- 代码注释使用英文，解释“为什么”而不是复述代码；复杂的 View Transition、路由方向计算、焦点恢复必须留短注释。
- 不写无意义注释，例如 `// set value`、`// click button`。
- 每个新增公共组件顶部可保留一行中文文件作用说明，但不要在模板中堆叠说明文字。
- TODO 注释必须包含责任和条件，例如 `// TODO(owner: frontend): remove mock fallback after API contract is live`，不能写无主人的“以后优化”。

### 10.4 样式和动画禁用项

- 禁止用全屏遮罩冒充主题切换或下推菜单。
- 禁止新建固定定位的透明层来拦截点击。
- 禁止 `transition: all`、无理由的无限循环动画、会造成布局跳动的高度自动动画。
- 禁止把 `prefers-reduced-motion` 当作可选项；必须提供降级。
- 禁止用 `!important` 解决 Naive UI 样式冲突；优先使用 `NConfigProvider`、CSS 变量和 `:deep()`。
- 禁止为 Phase 2/3 预先编写 Skill 运行、Playground、商业化和管理端业务代码。

## 11. 给执行 AI 的最终提示

> 先做小范围、可验证的任务；不要一口气重写全部页面。每次修改前先读目标文件和相关类型，修改后先跑局部检查，再跑全量构建。任何“看起来完成”的视觉效果都必须用 DOM、URL、键盘、滚动位置和截图/浏览器检查验证。特别是：超级菜单必须真实下推，主题切换必须使用 View Transition + `clip-path`，不能插入遮罩；页面前进和后退必须是相反方向；首页首屏必须让新用户理解 PromptOS 的用途。
